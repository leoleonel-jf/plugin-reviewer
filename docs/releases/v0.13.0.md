# Plugin Reviewer v0.13.0

Four commands stop reporting success, or promising a recovery, that was not true. These are the
four high findings of the independent review of 2026-11-20, and one low one.

## What changes for you

- **Two writers no longer lose a change.** `update ledger`, `update all` and `chain --seal` take a
  lock on `ledger.json.lock`, beside the ledger, from before they read it until after they replace
  it. A second writer waits up to 30 seconds, then exits `2` having written nothing, and can be run
  again. A record written by editing the JSON directly does not take the lock.
- **`rollback-preview` says what a backup proves.** A verified backup proves a target's recovery
  only when its digest is the target's own `before_digest`, or when the run created the target.
  Other intact targets move to `cannot_be_restored` with the reason `recovery_unverified`, and the
  run is `AT_RISK`, exit `1`. A run whose backup bundles several files, with at least one intact
  target that backup does not prove and nothing else changed, was `HEALTHY` and is now `AT_RISK`:
  the ledger format cannot tie such a backup to any one target.
- **`chain --seal` never breaks a chain.** It writes only when the sealed result verifies `INTACT`.
  A record with no chain before a sealed record, ahead of the first link or in a gap between two,
  is refused and named (exit `2`, file untouched).
- **`verify --chain` on a ledger with no records reports `UNCHAINED`** and exits `1`.
- **A configuration object shaped like a redaction marker is no longer copied** into the baseline,
  the ledger, or the dashboard, and it is read as configuration: its keys are items and a key
  under it resolves, so `drift` no longer confirms a false absence. Baselines captured before this
  version are not rewritten; capture a new one to correct an absence recorded that way.
- **`ledger.json.lock`** is listed in `.agent-audit/.gitignore` when the Skill creates the folder.
  An existing project's `.gitignore` is not changed: add the line yourself.

## Changes

- **`ledgerlib/locking.py`** (new): `ledger_lock`, used by `update.py` and `chain.py`;
- **`ledgerlib/rollback.py`**: `_backup_proves`, the reason `recovery_unverified`;
- **`ledgerlib/chain.py`, `verify.py`**: the seal verifies a copy first; the empty-chain finding;
- **`ledgerlib/scan.py`**: markers carry their provenance (`_Marker`), checked by text
  withholding, enumeration, and the pointer walk alike (the walk `drift` reuses);
- **references**: `LEDGER_INTEGRITY.md` (writer lock, sealing), `LEDGER_CHANGES.md` (sets and
  indicator), `LEDGER.md` (project `.gitignore`);
- **tests**: `dashboard/tests/test_ledger_lock.py` (7, real subprocesses) and new classes in
  `test_rollback.py`, `test_chain.py`, `test_update.py`, `test_scan.py`, `test_drift.py`; each
  guard proved by ablation.

No ledger field, identifier, label, or schema changed. A ledger written by 0.12.1 verifies under
0.13.0 and the reverse.
