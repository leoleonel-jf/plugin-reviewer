# Plugin Reviewer v0.14.0

Five reports stop coming back clean when they are not. These are five medium and low findings of
the independent review of 2026-11-20.

## What changes for you

- **`drift` sees a new Skill beside one it already knew.** A glob that matched something is
  expanded again, and a path that was not there at capture is `DRIFTED`, `appeared`. A baseline
  captured before 0.14.0 cannot be asked this way: the report lists its patterns in
  `unenumerated` and names them on stderr, without moving the exit code. Capture a new baseline to
  close it.
- **`lock --check` notices a missing MCP server** in a file that declares several. An entry is
  identified by kind, scope, anchor and name; older pins compare by the same key. One identity held
  twice is refused, naming it.
- **`verify` refuses a baseline id held twice**, in one ledger or across the ledgers given, or held
  by a baseline and a record. `lock` refuses to pin or compare an id that more than one baseline
  holds; an id one baseline shares with a record is `verify`'s finding, not the lock's. A ledger
  that holds either now fails `verify`, `build` and `update`.
- **A configuration file the parser could not read is a finding.** `parse_failed` names the probe
  and the file, whether the read failed before parsing or inside it; `parse_unavailable` is a TOML file on Python 3.10, which has no `tomllib`. The exit
  code is `1` and `update --strict` appends nothing. On Python 3.10 a scan whose adapter parses an
  existing TOML file now exits `1`.
- **The dashboard reads a configuration holding NaN or an infinity.** A capture stores them as
  `"nan"`, `"inf"` or `"-inf"`; `build` shows one found in an older ledger the same way, says so on
  stderr, and leaves the ledger untouched.

## Changes

- **`ledgerlib/scan.py`**: `attributes.glob` on every item of a glob probe; findings
  `parse_failed` and `parse_unavailable`; non-finite floats as their `repr`;
- **`ledgerlib/drift.py`**: `_glob_additions` re-expands recorded patterns; `unenumerated` per
  baseline;
- **`ledgerlib/lock.py`**: the name in the entry key; duplicate identities and ambiguous baselines
  refused;
- **`ledgerlib/validate.py`**: baseline ids counted beside record ids for duplicates;
- **`ledgerlib/build.py`**: `finite_payload` before the data island is serialized;
- **references**: `LEDGER_CHANGES.md`, `LEDGER_BASELINES.md`, `LEDGER_INTEGRITY.md`, `LEDGER.md`;
- **tests**: new classes in `test_drift.py`, `test_lock.py`, `test_dashboard.py`,
  `test_update.py` and `test_build.py`; each guard proved by ablation.

New fields are optional and additive. No identifier, label or required field changed.
