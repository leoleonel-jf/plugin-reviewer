# Plugin Reviewer v0.16.0

The review and the scan cover what they should, no less and no more. These are the last two medium
findings of the independent review of 2026-11-20, each observed in isolated sessions before it was
changed.

## What changes for you

- **A review reads only the package it reviews.** A link, a path or a reference that leaves the
  candidate's folder is reported with where it points, as something the package does not ship, and
  is not opened. Checking a claim against a primary source is still done on purpose. Instructions
  a skill gives for after it is adopted are described as what it does; text aimed at the reviewer
  is still a finding.
- **A Codex scan from a monorepo module sees the skills above it.** Project skills are read from
  the working directory up to the repository root (the nearest `.git`, a directory or a file), as
  Codex reads them, and recorded under `$REPO_ROOT/...`. Outside any repository only the working
  directory is read. A Codex baseline captured before is compared across adapter versions; capture
  a new one.

## Changes

- **`skills/plugin-reviewer/SKILL.md`**: ground rule *Read inside the package*; the data rule
  separates text aimed at the reviewer from instructions for after adoption;
- **`references/REVIEW.md`**: the skill checklist opens links inside the skill's directory only;
  *Before reading* bounds every kind to the copy;
- **`ledgerlib/adapters.py`**: anchor candidate `$ancestor:<name>`; probe field `up_to`, validated;
- **`ledgerlib/scan.py`**: a glob with `up_to` is asked in every parent up to that anchor, each
  level with its own pattern and its own absence;
- **`assets/adapters/codex.json`**: `$REPO_ROOT`, `up_to` on the project skills probe,
  `adapter_version` 3; schema and `references/LEDGER_BASELINES.md` updated;
- **evals**: case `SEC-005`, check `stays_inside_candidate_bundle`, optional `workspace` case
  field; 44 cases;
- **docs**: `docs/validation/review-inside-bundle-0.16.0.md`; the Codex row in
  `docs/research/2026-11-19-client-configuration-paths.md`;
- **tests**: new classes in `test_scan.py`, `test_adapters.py`, `test_drift.py`,
  `test_dashboard.py` and `evals/tests/test_eval_suite.py`; each guard proved by ablation.

No identifier, label or required field changed.
