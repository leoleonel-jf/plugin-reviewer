# Plugin Reviewer v0.16.0

The review and the scan cover what they should, no less and no more. These are the last two medium
findings of the independent review of 2026-11-20, each observed in isolated sessions before it was
changed.

## What changes for you

- **A review no longer follows the package out of its folder.** A link, a path or a reference in
  the candidate that leaves its folder is reported with where it points, as something the package
  does not ship, and is not opened. The review's own steps are unchanged: its references, a primary
  source chosen to check a claim, and the read-only comparison with your setup. Instructions a
  skill gives for after it is adopted are described as what it does; text aimed at the reviewer is
  still a finding. Observed in three sessions with one model before and after; not a pass rate.
- **A Codex scan sees the skills Codex loads, above the module and below the first level.**
  Project skills are read from the working directory up to the repository root (the nearest
  `.git`, a directory or a file) and recorded under `$REPO_ROOT/...`; outside any repository only
  the working directory is read. In every skills root a `SKILL.md` is found up to six directories
  down, never under a hidden directory, and the skills Codex caches under `.system` are their own
  layer. That is how codex-cli 0.146.0 listed them and what its source says, with two exceptions:
  a symbolic link to a directory is not followed here, and Codex's limits on the size of a root are
  not applied. A Codex baseline captured before is compared across adapter versions; capture a new
  one.

## Changes

- **`skills/plugin-reviewer/SKILL.md`**: ground rule *Read inside the package*; the data rule
  separates text aimed at the reviewer from instructions for after adoption;
- **`references/REVIEW.md`**: the skill checklist opens links inside the skill's directory only;
  *Before reading* bounds every kind to the copy;
- **`ledgerlib/adapters.py`**: anchor candidate `$ancestor:<name>`; probe field `up_to`, validated;
- **`ledgerlib/scan.py`**: a glob with `up_to` is asked in every parent up to that anchor, each
  level with its own pattern and its own absence; `max_depth` and `skip_hidden` bound a
  `**/<name>` walk, and `drift` walks with the limits each item recorded;
- **`assets/adapters/codex.json`**: `$REPO_ROOT`, `up_to` on the project skills probe, four
  skills roots walked six levels past hidden directories, the `.system` cache as its own layer,
  `adapter_version` 3; schema and `references/LEDGER_BASELINES.md` updated;
- **evals**: case `SEC-005`, check `stays_inside_candidate_bundle`, optional `workspace` case
  field; 44 cases;
- **docs**: `docs/validation/review-inside-bundle-0.16.0.md`; the Codex row in
  `docs/research/2026-11-19-client-configuration-paths.md`;
- **tests**: new classes in `test_scan.py`, `test_adapters.py`, `test_drift.py`,
  `test_dashboard.py` and `evals/tests/test_eval_suite.py`; each guard proved by ablation.

No identifier, label or required field changed.
