# Plugin Reviewer v0.17.0

The follow-ups the reviews of 0.16.0 left for after that release: the lock decides by the probe that
found each item, a re-asked absence reports each fact of its walk, a walk says when it could not
list a directory and a later comparison remembers it, and one more eval case on where a review may
read.

## What changes for you

- **`agent.lock` follows each probe's `lockable`, whatever kind of probe it is.** Items now record
  the probe that found them, so a literal path or a walked level from a probe without `lockable`
  stays out of the lock, as the Codex `.system` cache already did. A baseline captured by 0.16.0
  still works, by the pattern it recorded; capture a new one for the full rule.
- **`drift` reports an arrival, a refusal and an unlisted directory of the same absent pattern
  together**, from one walk, instead of the first alone.
- **A skills root with a directory that cannot be listed is reported** as `walk_incomplete`, in
  `scan` (a finding, so `update --strict` refuses) and in `drift`, instead of looking complete. A
  later `drift` against a baseline captured that way reports what it could not have seen as
  `capture_incomplete`, not as an arrival; capture again once the directory can be listed.
- **Eval case `SEC-006`**: a candidate claiming one of its outside files is a reviewer resource.

## Changes

- **`ledgerlib/scan.py`**: `attributes.probe` on every item; `expand_glob` collects the
  directories it could not list; `walk_incomplete` attribute and finding;
- **`ledgerlib/lock.py`**: matches the recorded probe (or a 0.16.0 baseline's `glob`), literal
  paths included; a `probe` or `scope` present and not text keeps the item pinnable by its kind;
- **`ledgerlib/drift.py`**: one walk per recorded absence, its facts as ordered rows;
  `walk_incomplete` for a pattern it could not list; `capture_incomplete` for what a partial
  capture could not have seen;
- **references**: `LEDGER_BASELINES.md`, `LEDGER_CHANGES.md`, `LEDGER_INTEGRITY.md`, `LEDGER.md`;
- **evals**: case `SEC-006`, fixture `evals/fixtures/reviewer-resource-claim`, a sentence in the
  `stays_inside_candidate_bundle` definition and in `RUN_PROTOCOL.md`; 45 cases;
- **tests**: new classes in `test_lock.py`, `test_scan.py`, `test_drift.py` and
  `evals/tests/test_eval_suite.py`; each guard proved by ablation.

No identifier, label or required field changed.
