# Plugin Reviewer v0.17.1

`drift` no longer lets the order of two overlapping patterns decide whether a new path is an
arrival.

## What changes for you

- **A new path reached by two overlapping patterns of one probe**, one captured whole and one only
  in part, is reported as `appeared`, whichever pattern comes first. Before, the partial pattern
  could report it as `capture_incomplete` although the complete one would have seen it. With every
  pattern that reaches it partial, it stays `capture_incomplete`. This only arises with an adapter
  that declares overlapping patterns of the same kind and scope; the bundled adapters do not.

## Changes

- **`ledgerlib/drift.py`**: a new identity keeps one row, and an answer from a complete capture
  replaces the `capture_incomplete` of a partial one;
- **references**: `LEDGER_CHANGES.md`;
- **tests**: `test_drift.OverlappingCoverageTests`, both orders and the all-partial control; the
  guard proved by ablation.

No identifier, label or required field changed.
