# Plugin Reviewer v0.17.1

A fix from the second review of 0.17.0: overlapping patterns in a custom adapter now decide a new
path by the strength of the evidence, not by which pattern sorts first.

## What changes for you

- **`drift` no longer depends on the order of overlapping patterns.** When two globs of one kind
  and scope reach the same new path and the baseline recorded one of them as partial and the other
  as complete, the path is reported as `appeared`, the evidence the complete capture gives. It
  stays `capture_incomplete` only when every pattern that reaches it was captured partially. The
  bundled adapters are not affected; a custom adapter with overlapping patterns is.

## Changes

- **`ledgerlib/drift.py`**: every recorded pattern is asked before any new path is reported; the
  row is chosen by whether a complete capture reaches the path, then deduplicated;
- **references**: one sentence in `LEDGER_CHANGES.md`;
- **tests**: `OverlappingCoverageTests` in `test_drift.py`, the same case with the partial
  pattern sorting first and last, and a control where every pattern is partial; the guard proved
  by ablation.

No identifier, label or required field changed.
