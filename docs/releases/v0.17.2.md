# Plugin Reviewer v0.17.2

A follow-up from the review of 0.17.1: which overlapping patterns decide a new path, now said
precisely and covered by tests. No behaviour changes.

## What changes for you

- **Nothing in what `drift` reports.** The documentation now says that, between overlapping
  patterns of one kind and scope that already had matches, the vote is of those that return the
  new path now, valid inside their anchor. A completely captured pattern that cannot be expanded
  now gives no vote, so a path only a partial pattern returns stays `capture_incomplete` and the
  failed expansion is reported on its own. A completely captured pattern whose walk now misses a
  directory still reports the paths it returns as `appeared`.

## Changes

- **`ledgerlib/drift.py`**: a comment in `_glob_additions` on which patterns vote; no logic change;
- **references**: `LEDGER_CHANGES.md` says which patterns vote and that a pattern recorded only as
  its own absence is answered by its own walk;
- **tests**: two cases in `OverlappingCoverageTests` (`test_drift.py`), a complete pattern that
  cannot be expanded now and one whose walk now misses a directory; proved by ablation.

No identifier, label or required field changed.
